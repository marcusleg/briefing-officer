# Briefing Officer Helm Chart

Deploys [Briefing Officer](https://github.com/marcusleg/briefing-officer), AI
summaries for your favorite news feeds, to Kubernetes.

The chart runs a single pod that serves the web app and refreshes feeds in the
background. Data is stored in an SQLite database on a PersistentVolumeClaim.

## Prerequisites

- Helm 3.8 or newer, for installing from an OCI registry.
- Credentials for one AI provider: OpenAI or an OpenAI-compatible API, Azure
  OpenAI, or Anthropic.
- A StorageClass that can provision `ReadWriteOnce` volumes, unless you bring
  your own claim or turn persistence off.
- Optional: a [Gateway API](https://gateway-api.sigs.k8s.io/) implementation if
  you want the chart to create an HTTPRoute.

## Installing

The chart is published to the GitHub Container Registry. Without `--version`,
Helm installs the latest release.

1. Create a secret named after the release that holds your AI provider
   credentials. The chart loads every key in it into the container's
   environment, so any setting from the
   [configuration reference](https://github.com/marcusleg/briefing-officer#configuration)
   can go here as well.

   ```sh
   kubectl create namespace briefing-officer
   kubectl --namespace briefing-officer create secret generic briefing-officer \
     --from-literal=OPENAI_API_KEY=sk-...
   ```

2. Write a `values.yaml`. See the [example](#example-values) below.

3. Install the chart:

   ```sh
   helm install briefing-officer \
     oci://ghcr.io/marcusleg/briefing-officer/charts/briefing-officer \
     --namespace briefing-officer \
     --values values.yaml
   ```

The secret's name is the release's full name: the release name when it already
contains `briefing-officer`, otherwise `<release>-briefing-officer`. The pod
does not start until the secret exists.

## Configuration

### Required settings

| Setting      | Where                                                | Notes                                                                                                            |
| ------------ | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| AI provider  | Release secret, non-secret parts optionally in `env` | Configure one of Anthropic, Azure OpenAI or OpenAI. If several are configured, they are tried in that order.     |
| `baseUrl`    | `values.yaml`                                        | Must be the URL users open in their browser. Derived from the first `httpRoute.hostnames` entry when left empty. |
| `authSecret` | Generated by the chart                               | Created on first install and kept across upgrades. Set it only if you need a fixed value.                        |

The AI provider variables are:

| Provider     | Variables                                                                          |
| ------------ | ---------------------------------------------------------------------------------- |
| Anthropic    | `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`                                             |
| Azure OpenAI | `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_RESOURCE_NAME`, `AZURE_OPENAI_MODEL`         |
| OpenAI       | `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` (defaults to OpenAI's own API) |

Other settings such as `FEED_REFRESH_INTERVAL_MINUTES`, `LOG_LEVEL` or single
sign-on (`AUTH_GENERIC_OAUTH_*`) are not chart values. Set them through `env`,
or through the release secret if they are sensitive.

### Example values

Exposes Briefing Officer at `https://news.example.com/` through an existing
Gateway and uses OpenAI, with the API key in the release secret created above:

```yaml
httpRoute:
  enabled: true
  parentRefs:
    - name: my-gateway
      namespace: gateway-system
      sectionName: https
  hostnames:
    - news.example.com

env:
  - name: OPENAI_MODEL
    value: gpt-4o

networkPolicy:
  enabled: true
  extraIngressRules:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: gateway-system
      ports:
        - protocol: TCP
          port: 3000
```

`baseUrl` is left out because it defaults to `https://news.example.com/`.

## Upgrading

```sh
helm upgrade briefing-officer \
  oci://ghcr.io/marcusleg/briefing-officer/charts/briefing-officer \
  --namespace briefing-officer \
  --values values.yaml
```

Database migrations run when the new pod starts. The chart runs a single replica
and replaces it on upgrade, so the app is briefly unavailable.

Leave drift detection off if you deploy with a GitOps tool such as Flux. The
generated `authSecret` cannot be read back during client-side rendering, so it
shows up as drift on every reconcile. Setting `authSecret` explicitly avoids
this.

## Uninstalling

```sh
helm uninstall briefing-officer --namespace briefing-officer
```

This deletes the PersistentVolumeClaim the chart created, and with it the
database. A claim passed in through `persistence.existingClaim` is left alone.
The release secret you created yourself is not deleted either.

### Application config

Credentials for the AI provider and for single sign-on go into a secret named
after the release (see [Configuration](#configuration)). Settings without a
chart value of their own can be passed through `env`.

| Name         | Description                                                                                                                                                                       | Value |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `authSecret` | Signs session cookies. Generated on first install and reused on every upgrade; set it only to pin a value. `AUTH_SECRET` in the release secret takes precedence.                  | `""`  |
| `baseUrl`    | Public URL the application is reached at, including scheme and trailing slash. Defaults to `https://<first httpRoute hostname>/`, or `http://localhost:3000/` without a hostname. | `""`  |
| `env`        | Extra environment variables for the application container. Appended after the chart's own, so an entry here wins on a name clash.                                                 | `[]`  |

### HTTPRoute

Exposes the application through a [Gateway API](https://gateway-api.sigs.k8s.io/)
HTTPRoute. Requests to `/api/health` from outside the cluster are redirected
to `/`.

| Name                    | Description                                                                     | Value   |
| ----------------------- | ------------------------------------------------------------------------------- | ------- |
| `httpRoute.enabled`     | Create an HTTPRoute.                                                            | `false` |
| `httpRoute.annotations` | Annotations added to the HTTPRoute.                                             | `{}`    |
| `httpRoute.parentRefs`  | Gateways the HTTPRoute attaches to.                                             | `[]`    |
| `httpRoute.hostnames`   | Hostnames the HTTPRoute matches. The first one also sets the default `baseUrl`. | `[]`    |

### NetworkPolicy

When enabled, the pod may only reach DNS in `kube-system` and HTTP(S) on public
addresses, so it can fetch feeds and call the AI provider but not services
inside the cluster or on private networks. All ingress is denied unless allowed
by `networkPolicy.extraIngressRules`.

| Name                              | Description                                                                                                    | Value   |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------- |
| `networkPolicy.enabled`           | Create a NetworkPolicy.                                                                                        | `false` |
| `networkPolicy.extraIngressRules` | Ingress rules for the NetworkPolicy, typically allowing your gateway or ingress controller to reach port 3000. | `[]`    |

### Persistence

The SQLite database lives on this volume at `/data/database.sqlite`. Without
persistence it is kept in an `emptyDir` and lost whenever the pod is replaced.

| Name                           | Description                                                                     | Value  |
| ------------------------------ | ------------------------------------------------------------------------------- | ------ |
| `persistence.enabled`          | Store the database on a PersistentVolumeClaim.                                  | `true` |
| `persistence.size`             | Size of the PersistentVolumeClaim.                                              | `1Gi`  |
| `persistence.storageClassName` | StorageClass of the PersistentVolumeClaim. Empty means the cluster's default.   | `""`   |
| `persistence.existingClaim`    | Use a PersistentVolumeClaim declared outside the chart instead of creating one. | `""`   |
